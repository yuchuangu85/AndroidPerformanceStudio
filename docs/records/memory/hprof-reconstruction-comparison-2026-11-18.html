三组实验分别回答不同问题

分组入口与包含工作明确排除
A · 完整导入Rust：host hash、worker 启动与 open、完整 typed snapshot、传输 / 解码 / fallback、App Presenter。Compose：真实默认 DesktopMemoryProfilerBackend.importHprof，包括内部复制、hash、分析、可选 TP 增补及持久化。二者都不计文件选择器和实际显示首帧；不是完整 UI 交互测试。
B · 核心阶段Rust：Heap::open、Engine::new、全部 histogram 与 findings。Compose：HprofParser.parse、MemoryDeepAnalyzer.analyze、per-heap histogram、查询 source 准备。另测 legacy perflib 的 snapshot + retained。外层输入 hash、进程启动、清理不计入内部阶段。各核心入口并非完全等工作量。
C · Studio 默认 TP安装包 native daemon；真实 loadTrace RPC、完整 HeapDump overview RPC；同轮串行测 Rust 核心及完整导入。不构造整个 Studio UI；不计 IDE 启动和 UI adapter。daemon 启动单列；RPC 合计不含它。

注意：perflib 是 Studio 的 legacy 参考链路。安装包的默认 HPROF flag 指向 TraceProcessor；运行中的 GUI 会话仍可能存在 property / server / user override。本次直接测量安装包默认后端，不声称已检查某个用户会话的有效 flag。

D

内存：核心 RSS 更低，不代表整个 IDE 的占用

使用 macOS /usr/bin/time -l 的 maximum resident set size，统一换算 GiB（2³⁰ 字节）。它不同于 JVM 的 Xmx，也不是多个进程同时占用之和。

完整导入 A 组的外层 RSS：Rust 0.953 GiB，Compose 4.361 GiB。Rust 的 host / worker 并发占用未以同时求和方式采集，因此不宣称完整产品进程树的内存节省比例。没有从本轮数据推导内存泄漏率或长期稳定性。

E

当前重构的优势：机制、收益与约束一起说明

这里描述已落实的 HPROF 链路，不将单一文件的收益泛化到所有 Profiler、所有平台或整个 Rust 迁移。各单点收益来自另一组优化前后实测，不能相加为总收益。

1

建图专用批量引用扫描，减少临时对象与重新定位

缓存继承字段布局，只提取引用 ID；保持已有读取缓冲，按对象数与字节数批次检查来源。静态字段、数组与弱引用语义仍按原路径处理。

保留约束
字段详情与数组值仍可按需读取；入口、批次、完成及惰性查询的身份检查保留。
收益证据
整条链路已反映在 0.912 秒解析与 2.382 秒引擎就绪中；本轮未独立拆分建图扫描器的单项收益。

aps-hprof-engine/src/references.rs · analysis.rs / Graph::build_named_with_storage

2

Native 归属按文件顺序批量读取，复用已计算结果

对 Cleaner、thunk、registry 的必要引用和整数大小做选择性读取，批次按文件偏移排序；最终归属仍按原 Cleaner 顺序赋值，避免数据语义被重排。

保留约束
保留继承 / shadowed 字段、first-non-null、missing 与 zero、原先 last-Cleaner-wins 语义；不额外添加重复 native bytes。
收益证据
另一组 7 次配对组件实测：1,713.625 ms → 82.116 ms，约 20.87 倍；不是本轮三方样本的独立阶段。

aps-hprof-engine/src/native/scanner.rs · native.rs / map_native_sizes / scan_native_sizes / sort_records

3

保留完整 hash，但使用系统加速 SHA-256

macOS 使用 CommonCrypto；其他平台保留 portable 实现。运行时不依赖外部命令，也没有新增依赖。

保留约束
Host 与 worker 共三次完整 hash 保留；加速不是跳过内容身份、文件句柄或路径身份检查。
收益证据
优化前后 7 次配对导入：host hash 431.218 ms → 61.984 ms。本轮 A 组实测为 65.194 ms。

aps-hprof-engine/src/sha256.rs · aps-hprof-engine/src/sha256_portable.rs

4

Histogram 共享扫描，Retained Summary 不再创建分页行

多个 heap 的 histogram 在同一节点扫描和 dominator 遍历中聚合，保留各自祖先抑制状态；retained summary 直接累加相同可见根，不为求总数构造页面行。

保留约束
class object、映射类分组、heap-local ancestor 抑制、未知值与 native 值保持；隐藏 class node 下的可见根仍计入。
收益证据
本轮共享 histogram 中位数 263.283 ms。既往单次诊断有收益，但不将单次结果当统计性加速结论。

aps-hprof-engine/src/histogram.rs · Engine::histogram_bundle / retained_summary

5

有界投影缓存与单次最终编码，减少重复工作

worker 缓存受摘要作用域约束的 omitted-heap 编码投影，最多 32 MiB / 64 项；最终响应只编码一次，避免为了预算再构造同一响应。

保留约束
cache hit 仍检查来源和图；不写磁盘持久缓存。响应预算、超时和取消保留。worker 进程隔离不等于 OS 安全沙箱。
收益证据
既往优化前后完整 snapshot 阶段 1,124.816 ms → 723.655 ms；本轮 A 组为 742.322 ms。不能单独归因给某一个缓存。

aps-memory/src/worker.rs · HistogramCache / snapshot_response / encode_response

6

UI 共享不可变分类树，减少重复渲染准备

classifier tree 和 visible paths / warning markers 复用；筛选、排序、展开、刷新、重置与快照切换按相应状态失效缓存。

保留约束
旧回调数据保持不可变；类 / 包视图、隐藏 heap、null 与 zero、warning 更新仍有回归覆盖。
收益证据
已覆盖缓存与失效行为，但没有测出 GPU 首帧或原生 UI 渲染速度提升；不把 Presenter 时间当首帧。

aps-app/src/import/memory/state.rs · aps-app/src/import/memory/classes.rs

7

Mapping 重载绑定快照身份，成功后再替换会话

Mapping 同时校验 workspace generation、load generation 与 snapshot ID；先在后台取得完整新快照，成功后才替换原 worker session。

保留约束
陈旧完成不能覆盖另一标签的数据、错误与通知；失败保留原会话和已发布页面；mapping 文件及条目预算保留。
收益证据
同名文件、相同代号和 A 到 B 切换已有回归；此项属于正确性与生命周期修复，没有独立性能百分比。

aps-app/src/import/memory/mapping.rs · memory_mapping_is_current / memory_import_mapping

8

Dominator 请求互不作废，恢复标签只补缺失页面

不同父节点请求共用快照 epoch，重复请求不使原请求失效；快照挂起使旧回调失效但保留已发布页，恢复时只补缺失查询。

保留约束
每个完成只清理自身 pending；失败可重试；snapshot ID 与 epoch 共同约束回调。独立请求并不等于 worker 内的并行计算。
收益证据
逆序完成、重复、失败重试、快照恢复与 wraparound 有回归；切换延迟与查询加速未单独测量。

H

已确认的收益，与仍然开放的验收项

“更快的数据链路”与“整个产品全面优于参考实现”是不同结论。本报告只支持前者，并记录下一步需要补齐的实测。

可以据此决策

✓
继续采用紧凑记录、批量引用扫描及共享聚合。在这份真实大文件上，性能、内存与前后等价都有证据。
✓
保留 source identity、hash 与完整快照发布。已有速度提升不依赖删除这些约束。
✓
将 UI 缓存收益与数据导入收益分别评估。现有缓存回归覆盖不能替代真实首帧测量。

不能据此宣称

!
整个 Rust 重构或每个 Profiler 都快同样倍数。本次只测 HPROF、一个文件、一台机器。
!
已完成全部原生 UI、真机或跨平台验收。此前只确认临时 Release 首页和文件选择器；导入后完整键鼠与渲染验收仍开放。
!
已完全对齐 Android Studio 的所有语义与交互。TP / perflib、分组、shallow、retained 与 UI 功能范围均有边界。

下一轮验证的优先级

优先项需要补充的证据完成前的表述
原生导入首帧解锁的稳定 GUI 会话；从操作触发到首个完整可见帧的同钟计时，并完成页面切换 / 详情展开。当前只有后端 / Presenter 就绪数据，不估算首帧。
更广的输入与冷态不同大小、4 / 8 字节 ID、多 classloader、异常 / 修改文件，以及独立冷盘和已运行 JVM 的样本。只报告当前输入与缓存条件，不推导普遍加速。
完整进程树内存同步采集 host、worker、daemon、JVM / IDE 的并发 RSS 与长期导入 / 关闭循环。只报告入口进程的最大 RSS，不推导完整产品树占用。
进一步优化继续分离 graph / retained / snapshot 编码的 CPU、分配与拷贝；单变量修改并复用等价校验。未测单点不写预期节省毫秒或收益百分比。
