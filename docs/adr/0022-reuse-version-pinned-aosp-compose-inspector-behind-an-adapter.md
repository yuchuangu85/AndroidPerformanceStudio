# Reuse the version-pinned AOSP Compose Inspector behind an adapter

Compose inspection capability parity uses version-pinned AOSP Compose inspection agents and protocols rather than extending the current Semantics reflection into a second Compose runtime inspector. The minimum required Apache-2.0 AOSP source snapshot is vendored with its provenance, notices, hashes, and auditable patches instead of relying on a submodule or build-time checkout; a dedicated host adapter converts upstream protobuf data into Android Performance Studio's stable inspection model, keeps AOSP version selection and deployment outside feature UI and archives, and retains the existing Semantics collector only as an explicit degraded path. This accepts the cost of maintaining pinned upstream revisions and adapters to keep builds reproducible and avoid coupling the product model to Android Studio Transport or reimplementing unstable Compose internals.
