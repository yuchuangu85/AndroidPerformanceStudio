> 2026-10-31 布局更新：按用户要求，以本机 DeepSeek Harness 0.2.1-rc.5 为聊天参照。
> 对话窗口只保留聊天；管理功能移入“设置 → AI 设置”。下文的新布局覆盖早期
> “常驻右侧证据栏”和“窗口内管理标签页”方案。逐项参照、当前实现范围及差距见
> [DSH 聊天对齐记录](dsh-chat-parity.md)。代码存在、自动化截图、原生交互和真实 Provider

## 1. 目标

在已有单次 AI Analysis Finding 之外，提供一个**绑定 Analysis Session 的对话窗口**，作为 Main Agent 的统一前端，让用户可以针对当前性能问题继续提问、请求解释、比较证据、查看源码依据，并请求已授权的子 Agent/Skill 完成受控分析。

这个窗口不是通用 ChatGPT 页面。每条消息都必须能回到当前业务 Entry Point、Profiler、Analysis Session、Performance Evidence 和 Source Candidate；主 Agent 的子任务和 Skill 调用也必须可见、可取消、可审计。

## 2. 入口

对话窗口可以从以下位置打开：

1. Layout Inspector 的 Finding 或当前选中节点。
2. CPU/Simpleperf 的有界性能摘要、函数、调用树节点或 Stack Chart block。
3. 方法录制的有界方法耗时/调用次数摘要，以及内存、帧、启动、电量、网络、GPU、基准回归、Trace 诊断和源码元数据页工具栏的“AI 分析”。新入口只提交当前页面发布的同一份有界证据，不读取额外文件或自动授权源码。
4. Trace/Frame/Startup/Memory 等 Profiler 的 Finding。
5. Analysis Session 历史记录中的“继续分析”。

没有可用 Analysis Session 时仍可打开空白聊天及历史；输入区应明确提示未绑定证据并禁止发送。
新建会话或打开窗口不自动创建模型请求，也不把任意工作区路径升级为授权上下文。

### 布局检查器入口

- 在布局检查器选择节点后，点击“问题”（FINDINGS）区的“AI 分析”（Run AI）；桌面宿主直接打开全局 AI 会话的待确认预检，不再先弹出旧页面确认框。独立运行布局检查器仍保留原本的本地预检和源码授权流程。
- 发起时暂停自动扫描，绑定当前快照、窗口和时间线。默认只提交有界脱敏的布局结构、尺寸和规则证据，不发送截图、View/Compose 运行时文字或源码片段；失效选中节点不自动降级为全窗口分析。
- 大布局不再因正常裁剪而一律拒绝：“仅性能数据”模式可发送显式不完整的摘要，树投影最多 200 个节点、子树深度 8、每节点 24 个子节点，JSON UTF-8 最多 48 KiB；父节点可另附作上下文，仍计入节点总数。覆盖标记、被裁剪子节点数和规则裁剪状态随证据发送，摘要指标不冒充原布局完整指标；模型不可根据未包含节点推断不存在问题。源码模式及缺少有效覆盖标记的截断输入仍需缩小范围。
- 性能 payload 使用字段白名单，不发送通用布局 JSON：保留显示尺寸/密度、节点 ID、控件类型短名、边界、可见性、透明度、父子关系、文字长度、原布局/投影指标和覆盖范围；移除包名、时间、截图存在标记、资源名称及无障碍描述长度。规则只包含规则 ID、级别、节点引用和数值参数（`count`、`threshold`、`depth`、`ratioPercent`），不复制规则自由文本及任意参数。完整类名、资源名、文字与描述原文继续留在本地，节点定位和显式授权的源码匹配不依赖向 AI 发送这些本地元数据。
- Provider、模型、Agent、报告格式、报告语言和权限取自已保存设置，并在本次预检前冻结；后续设置变化不能替换待确认请求。页面不读取宿主凭据，也不在全局分析失败后回退旧 OpenAI 网关。
- 只有在全局会话点击“确认”后才发起模型请求。结构化结果保留 `layout:<nodeId>` 引用并回写原布局的 Findings；切换快照、窗口或时间线、取消操作及页面释放都会终止旧任务，过期结果不会写入新布局。
- 全局取消会传播回布局调用方；取消尚未确认的分析不发起 Provider 请求。报告保持真实 Provider 来源，并沿用 HTML/Markdown 报告输出策略。
- 等待模型响应不计入 CPU 预算，只受请求总耗时限制；根 Agent 与子任务的实际 JVM 执行线程 CPU 用量累计检查。真正超过 CPU 限额仍返回 `E_CPU_BUDGET`，模型等待超过请求 wall timeout 仍按可重试的 `E_PROVIDER_TIMEOUT` 处理，不因网络较慢误报 CPU 超限。

## 3. 窗口布局

```text
┌ AI Chat ────────────────────────────────────────────────────────────────┐
│ 会话侧栏                 │ 会话标题                                   │
│ 新建 / 搜索              │                                            │
│ 最近 / 置顶会话          │                  用户问题气泡               │
│ 会话菜单                 │ AI 结构化回答 / 引用 / 工作过程              │
│                          │ [Evidence] [Source] [已验证 Artifact]       │
│                          │                                            │
│                          │ 排队问题（编辑 / 移除）                     │
│                          │ 当前有界证据                               │
│ 归档 / AI 设置           │ 输入问题…                                  │
│                          │ [上下文] [模型列表]               [发送]   │
└──────────────────────────┴─────────────────────────────────────────────┘
```

侧栏在窄窗口可折叠；聊天列与输入框居中，输入框独立停留在底部。Provider、Agent、Skill、
执行策略、连接和导入配置只在 AI 设置页管理。证据引用仍直接可见于消息，但不再要求常驻
右侧面板；点击引用打开精确、只读详情。历史缺少 canonical payload 时显示 unavailable，
不从另一报告补齐同名 ID。源码正文是否会发送仍需在本次预检中明确确认。

局部字体、颜色、圆角与布局规则由 `DshChatStyle.kt` 管理，不改变其他 Profiler 的共享主题。
Web CSS 像素与 Compose dp/sp 的字体栅格、原生窗口和交互仍需分别验证。

### AI 设置页分类（2026-11-02）

- 顶部将“Provider / Agent / Skill / 执行策略”展开成一组标签，复用 Layout Inspector
  “刷新 / 自动扫描”相同的 `SegmentedSelector`，使用 `COMPACT_OUTLINED` 样式；不再通过下拉框切换分类。
- 下方只显示选中标签对应的功能，保留各分类原有的连接、配置读取、注册管理和执行策略行为，
  不同时铺开所有表单。切换标签不等于保存草稿或授权执行。
- 原“连接”改名为“Provider”，顶部选择 Codex、Claude 或自定义（OpenAI 兼容），下方只显示
  当前连接卡片；原独立 Provider 管理页不恢复。Codex/Claude 可显式读取对应本地配置，自定义
  手动填写。切换保留各自草稿，但只有“保存并应用”成功才切换对话使用的 AI。
- 对话的下一次发送、重试或队列预检读取最新已保存的 Provider、模型和分析 Agent；已预检或
  运行中的请求保持原快照。普通聊天仍使用受限 `aps.chat`，不扩大工具或证据授权。
- 对话输入区的模型按钮只弹出当前 Provider 的模型列表，不导航设置页。列表复用已应用连接
  的版本化缓存，缺失时获取，菜单可显式刷新；加载/空/错误有独立状态，选模型不发送消息。
- 再次点击 AI 入口会激活已有窗口并恢复最小化，而不是仅重复写入可见状态；草稿、历史和
  已运行工作不因前后台切换而重建或重放。
- 首次默认“Provider”；后续通过现有 `ApplicationUiSettings` 保存最后选择，返回该页和应用重启
  后恢复。旧 `CONNECTION`、旧 `PROVIDER` 以及未知或损坏值均打开新的 Provider 连接页；
  读取分类不重写已有偏好，不因导航状态损坏导致设置页不可用。
- 该设置页全页沿用共享 `ViewerTypography` 的 16sp/13sp/11sp 三档；DSH 风格聊天窗口继续使用
  自己的局部 tokens，不随此次设置页整理变化。

## 4. 消息类型

### 会话删除

会话条目的菜单提供“删除”，点击后显示包含会话标题与不可撤销说明的二次确认框。
取消或关闭不会删除记录或停止运行。确认后由宿主调用会话服务，删除该会话及其内部
Agent 子任务的消息、结果和审计投影；当前会话删除后打开新会话，其他会话删除不改变
当前选择、草稿或运行。用户分支必须独立处理，存在分支依赖时拒绝删除，不做部分删除，
不把删除记录扩展为移除共享的 Artifact 文件。

### 用户消息

- 自然语言问题；
- 自动绑定当前 conversation 和 parent turn；
- 可附加用户选择的 Finding、Evidence 或 Candidate；
- 不能指定未经系统确认的路径和行号作为事实。

### AI 消息

AI 响应应包含结构化部分：

- 直接回答；
- 结论置信度；
- Evidence 引用；
- Source Candidate 引用；
- 相关 Finding；
- 可执行但只读的下一步建议。

自然语言正文可以展示，但引用和动作必须来自结构化字段，不能从 Markdown 中猜测路径。

如果主 Agent 调用了子 Agent、Skill 或脚本，消息还应显示：调用名称、版本、状态、权限、耗时、输入/输出摘要和产物引用。

### 系统消息

用于展示：

- payload 需要用户确认；
- 源码上传未授权；
- 当前 Snapshot 已 stale；
- Candidate 存在歧义；
- 请求取消、超时、限流或需要重试；
- 重新分析产生了新的 Session；
- Skill/脚本没有权限、超时或产生部分结果。

## 5. 对话上下文规则

### 默认上下文

每个 turn 默认继承：

- `baseSessionId`；
- 当前 Profiler 和 scope；
- 当前 Finding；
- 已引用 Evidence ID；
- 已授权 Candidate ID；
- Source Snapshot 和 Build Evidence 身份；
- prompt/payload policy 版本。

### 扩大上下文

当用户提出“看看整个报告”“比较另一个函数”或“检查相关源码”时：

1. 先生成新的 Payload Manifest；
2. 显示新增 Evidence/Candidate、片段、大小和隐私影响；
3. 超出预算或缺少授权时阻止发送；
4. 用户确认后创建新的 child Analysis Session 或 turn；
5. 不修改原始 Session。

### 历史和重新分析

- 每个 turn 保留 parent turn 关系；
- 会话列表保存置顶、重命名、归档元数据，用户问题仅保留有界、脱敏且移除已知源码片段/证据正文的投影；旧历史缺失问题保持缺失，不根据 hash 编造。
- 连续追问由宿主从同 Analysis Session/context 的成功结果读取最近 4 个 turn，每段问题/回答最多 2048 字符，作为单独的 `untrustedConversationContext`；外部传入的历史列表不授信。审批冻结后不重新读取或扩张历史。
- 分支首轮仅使用父会话截至选定 turn 的授权历史；新分支的持久化消息只保存真实执行的 turn，不伪造父消息副本。
- 新建取消当前运行并重置当前选择，但不删除既有历史；打开历史、置顶、重命名、归档和复制 ID 不发起 Provider 请求。恢复不重放，继续前必须显式绑定可验证的当前证据。
- 恢复含源码的会话时，绑定当前证据不会继承旧的源码发送授权；需要重新勾选“包含已授权源码”，再进入本轮预检。未再次授权时禁止发送，并明确显示原因。
- 修改源码、切换 Snapshot、切换模型或 prompt version 后不得覆盖旧结果；
- 重新分析创建新的 Analysis Session；
- 历史 Finding 的源码哈希不一致时显示 `stale`，不能静默跳到新文件的相同行号。

## 6. Agent、Skill 和脚本调用

- 主 Agent 只能调用注册表中的子 Agent/Skill；模型不能通过文本拼接任意调用名。
- 每个调用声明输入/输出 schema、能力、权限、超时、输出大小和是否允许网络/源码/设备访问。
- 外部 Agent/Skill 必须经过来源、版本、哈希/签名和用户信任确认。
- 已具备合格原生后端的 Python/Node 脚本运行在临时工作目录和只读输入挂载中，默认无网络、无宿主凭证、无任意路径和无设备写操作；没有合格后端的平台保持 unavailable，不把 UI 开关当成隔离能力。
- 脚本审计只保留有界、脱敏且符合存储 schema 的状态/来源/哈希等投影；不把任意 stdout/stderr 原文直接写入聊天历史。脚本失败不得伪装成 AI 结论。
- 需要扩大 Evidence、上传源码、联网或执行副作用操作时，窗口必须先显示确认。

## 7. 隐私和安全

- 默认只发送当前 Session 的结构化证据；
- 源码片段必须逐 workspace 授权；
- 提供“仅性能数据”模式；
- 不发送完整源码、完整索引、绝对路径、凭证和 ignored/sensitive 文件；
- 源码、注释、符号名和用户问题中的代码文本均视为不可信数据，不视为系统指令；
- HTTP redirect 跨主机时不得转发 Authorization；
- 默认不归档模型原始响应；本地对话历史应保存最小结构化消息，显式导出时再生成脱敏副本；
- 对话动作只能访问 allowlist 中的只读 Evidence/Candidate，不得任意访问文件系统。

## 8. 状态和错误

窗口需要区分：

- `Queued`：等待请求执行；
- `Preparing`：构建上下文和 Payload Manifest；
- `AwaitingConfirmation`：等待用户确认上传范围；
- `Running`：请求已发送；
- `Succeeded`：回答已通过 Schema/ID 校验；
- `Cancelled`：用户取消，不再写入已取消 turn；
- `RetryableFailure`：网络、超时、限流；
- `PermanentFailure`：凭证、Schema、未知 ID、授权或 Snapshot 错误。

取消后 UI 应立即停止等待；底层 HTTP 晚到的响应不能写入已取消的 turn。
停止仍在等待 UI 交互锁的预检，也必须释放 `preparing` 门禁；不能因为尚未进入预检主体而永久禁用发送、新建或历史选择。

## 9. 聊天交互与验收

- 会话菜单采用置顶、重命名、分支、归档、复制 Session ID；归档视图支持取消归档。默认菜单不增加永久删除，运行中归档需确认停止。
- Enter 发起本次预检而非绕过审批；Shift+Enter 换行，IME composition 中不提交；空输入上箭头取回问题；两个独立 Escape 按键停止，长按重复不等同两次按键。
- 发送按钮与 Enter 共用真实可执行上下文门禁；外部请求的预检预览只用于展示，不能充当当前报告的 canonical evidence。未绑定时显示操作提示，不呈现“可发送但无响应”的状态。
- 首次等待上下文从不可用变为可用时保留未发送草稿；切换已有报告仍新建隔离会话，不把旧报告草稿自动发送到新报告。
- 忙碌时可排队、编辑或移除问题；当前本地队列不是 DSH 的持久化 Inbox，也没有中途 Steer。后续问题必须使用各自冻结的上下文和独立审批，不因入队自动获得发送权限。
- 复制提供成功/失败反馈；阅读历史时保留滚动位置并提供回到最新消息操作。新建/搜索提供 Cmd/Ctrl+N、Cmd/Ctrl+K 快捷入口。
- 附件、上传、语音、任意工作区 Chat、完整 Token 计量、DSH 扩展插件等不在本轮已实现范围；不要渲染成看似可用的控件，详见对齐记录。

保留的业务验收条件：

- 从 Layout Inspector Finding 打开对话窗口，并保留 Evidence/Candidate 引用。
- 用户可以追问“为什么”“证据是什么”“还有哪些候选原因”。
- 回复只能引用当前 Session 中的 ID。
- 未授权源码、超预算和 stale Snapshot 都会阻止或提示，而不是静默发送。
- 取消、超时、重试和重新分析都有明确状态。
- 对话历史能够恢复，但不保存凭证、绝对路径、完整源码或模型原始响应。
- CPU/Simpleperf 已接入统一窗口：默认仅性能数据，一次发送一份最多 8 KiB（UTF-8）的关键摘要。热点最多 8 个、线程最多 3 个，范围、权重语义和质量只发送一次；候选仅来自已加载投影，不宣称完整全局 Top N。选中对象优先、失效选择不回退；源码需另行显式授权，不默认发送原始样本/调用树/时间线/Marker 或完整报告。
- 主 Agent 可以在一个问题中调用至少一个内置 Skill，并在窗口中展示调用摘要和结构化输出。
- “设置 → AI 设置 → 执行策略 → 报告输出”可选择 `HTML (.html)` 或 `Markdown (.md)`，默认 HTML；旧配置和未知格式回退 HTML，不覆盖已有 Provider、模型、Agent 或权限。
- 报告格式在新预检时冻结并计入确认 hash；设置变更只影响之后的新报告，不替换待确认、运行中或历史报告的格式。格式选择不自动授予 `WRITE_ARTIFACT`，普通聊天仍无报告写入权限。
- 报告语言支持自动、英语和简体中文。新预检把选择冻结到可信请求字段和确认 hash，OpenAI/Codex Responses 与 Claude 的系统提示都要求 summary、finding 标题、解释、建议及报告正文使用该语言；性能标识符、路径和证据 ID 保持原文。语言变化不改变报告证据的 canonical session/hash，只影响之后的新执行。
- 失败、不可用及中断消息提供对应 turn 的“重试”，保留原问题（报告入口可无问题）并读取最新已保存设置，创建新预检与独立确认；预检阶段失败也可在修正设置后重试。重试不覆盖未发送草稿，不自动调用 Provider，不绕过报告证据绑定或源码授权，运行中禁止重复提交。
