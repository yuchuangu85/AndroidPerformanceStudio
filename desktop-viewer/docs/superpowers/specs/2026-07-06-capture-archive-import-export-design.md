# 采集归档导入导出设计

## 目标

将现有 **高级 / Advanced** 菜单改为 **文件 / File**，并把仅导出
Visible Window Views 原始文件的功能升级为可离线复现当前检查结果的采集归档：

- **导出 / Export**：保存当前布局快照、截图及可获得的原始采集文件。
- **导入 / Import**：打开本软件导出的归档，并在现有层级、画布、属性和问题界面中展示。

归档默认使用 `.apinspect` 扩展名，内部保持标准 ZIP 结构；导出和导入也支持
`.zip` 扩展名。

## 文件菜单

原生菜单栏中的 **高级 / Advanced** 重命名为 **文件 / File**，包含：

1. **导入 / Import**
2. **导出 / Export**

菜单项使用系统文件选择器。导出时提供 `.apinspect` 和 `.zip` 两种过滤器，默认
文件名由应用包名和采集时间构成，并默认使用 `.apinspect`。导入时接受这两种
扩展名，但最终以归档清单和内容校验为准，而不是仅信任扩展名。

导出只有在内存中同时存在布局快照和截图时可用。导入和导出执行期间禁用两个
菜单项，避免并发覆盖状态或目标文件。

## 归档格式

版本 1 的归档结构为：

```text
manifest.json
capture/layout-snapshot.json
capture/screenshot.png
raw/visible-window-views.zip
raw/visible-window-views.txt
```

前三项是必需文件；`raw/` 下的文件是可选诊断附件。

`manifest.json` 至少包含：

- 归档格式标识与格式版本；
- 创建本归档的软件版本；
- 应用包名和采集时间；
- 协议主、次版本；
- 每个归档文件的相对路径、字节数和 SHA-256；
- 可选附件是否存在。

归档不包含用户设置、面板尺寸、主题、语言或设备授权信息。

## 导出流程

1. 从当前 `InspectorState` 取得布局快照与 PNG 截图。
2. 使用现有 `ProtocolCodec` 将快照编码为规范的 JSON。
3. 如果当前状态来自已导入归档，保留其可选原始附件。
4. 如果当前状态来自实时或手动设备采集，则调用现有
   `dump-visible-window-views` 链路取得原始 ZIP，并用现有渲染器生成 TXT。
5. 计算每个内容文件的长度与 SHA-256，生成 `manifest.json`。
6. 在目标目录写入临时文件，全部成功后再原子替换最终文件。

布局快照和截图是导出成功的必要条件。设备原始 Visible Window Views 抓取失败
时仍可导出可重新展示的归档，但归档中不写入对应可选附件；成功对话框明确提示
归档已生成以及是否缺少原始附件。

导出 `.apinspect` 与 `.zip` 时内容完全相同，仅文件扩展名不同。

## 导入流程

1. 文件选择器读取用户选择的 `.apinspect` 或 `.zip`。
2. 归档读取器先校验文件总体积、条目数量、条目名称和单条目大小。
3. 解析 `manifest.json`，验证格式标识、归档版本、必需条目、长度和 SHA-256。
4. 使用现有 `ProtocolCodec` 解码 `capture/layout-snapshot.json`，继续执行协议主
   版本兼容性检查。
5. 校验 `capture/screenshot.png` 的 PNG 文件签名和尺寸可读取性。
6. 将快照与截图交给现有 `InspectorStore.loadCapture`，重新运行当前分析器并
   刷新层级、画布、属性和问题列表。
7. 保存可选原始附件到当前会话状态，使导入后的内容再次导出时不会丢失。

导入成功后自动关闭自动扫描。导入期间不清空当前界面；只有归档完全验证且能够
解码后才一次性替换现有状态，因此失败不会破坏用户当前正在查看的内容。

导入完成后的连接状态显示为离线归档状态，而不是伪装成实时设备连接。为此给
应用状态增加明确的导入来源或离线状态，并在顶部状态文字中提供中英文显示。

## 组件边界

新增聚焦的采集归档组件，负责：

- ZIP 写入和读取；
- manifest 序列化与校验；
- 条目大小和摘要校验；
- `.apinspect` 与 `.zip` 的同格式处理。

归档组件不直接操作 Compose 状态、文件选择器或 ADB。桌面应用负责：

- 从 `InspectorState` 组装导出输入；
- 按需调用 `LiveDeviceClient.dumpVisibleWindowViews`；
- 调用保存/打开文件选择器；
- 将导入结果提交给 `InspectorStore`；
- 显示本地化的进度、成功和失败反馈。

现有 `VisibleWindowViewsTextRenderer` 继续负责原始 ZIP 的 TXT 表示。原有
`VisibleWindowViewsExporter` 的双文件目录导出入口由新归档导出取代，其可靠的
临时文件和原子替换行为保留到新实现中。

## 安全与兼容性

- 归档内容直接按固定条目名读取，不将任意条目解压到文件系统，避免 ZIP 路径
  穿越。
- 拒绝重复条目、绝对路径、`..` 路径、加密条目和超出限制的条目。
- 对 ZIP 总压缩大小、总解压大小、条目数量、快照大小和截图大小设置上限，避免
  ZIP bomb 和内存耗尽。
- 校验 manifest 声明与实际条目完全一致；允许未知的可选条目仅用于未来小版本
  扩展。
- 不支持的归档主版本或采集协议主版本给出明确错误，不部分加载。
- `.zip` 只有在包含有效 `manifest.json` 和必需采集内容时才作为采集归档导入；
  旧的独立 `visible-window-views.zip` 会被识别为不完整归档并给出错误。

## 本地化与反馈

新增中英文字符串：

- File / 文件
- Import / 导入
- Export / 导出
- Choose archive to import / 选择要导入的归档
- Choose export file / 选择导出文件
- Importing / 正在导入
- Exporting / 正在导出
- Import succeeded / 导入成功
- Import failed / 导入失败
- Export succeeded / 导出成功
- Export failed / 导出失败
- Offline archive / 离线归档

错误信息保留底层原因，但通过现有字符串层补充用户可理解的操作上下文。

## 测试

自动化测试覆盖：

- 文件菜单中英文标题、顺序、启用状态和回调；
- 文件选择器扩展名与默认文件名处理；
- `.apinspect` 和 `.zip` 导出内容一致；
- manifest、快照、截图、原始 ZIP/TXT 及摘要正确；
- 无原始附件时仍能成功导出和导入；
- 导出临时文件清理、原文件保护和原子替换；
- 导出后再导入可还原包名、布局树、截图和分析结果；
- 导入后再次导出会保留可选原始附件；
- 导入成功关闭自动扫描并切换到离线归档状态；
- 取消选择不改变当前状态；
- 缺少 manifest、快照或截图；
- 摘要、长度、PNG 签名或协议版本错误；
- 重复条目、路径穿越、过多条目和超限解压大小；
- 导入失败时现有界面状态保持不变。

验证顺序为目标单元测试、Desktop 模块测试、完整 `./gradlew test`、
`git diff --check`，并进行一次真实文件选择器的导出—导入桌面冒烟验证。

## 非目标

- 导入普通图片、任意布局 XML 或旧的独立 Visible Window Views ZIP。
- 在归档中保存多帧时间线。
- 在导入模式下继续连接或控制原设备。
- 对归档进行加密、签名或云端同步。
- 修改 Android Agent 的实时采集协议。
