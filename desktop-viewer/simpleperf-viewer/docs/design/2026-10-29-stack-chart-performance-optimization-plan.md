# CPU Stack Chart 性能优化方案（未实现）

- 状态：**未实现**。目前仅完成只读诊断和方案记录。
- 日期：2026-10-29。
- 范围：CPU Profiler / Simpleperf Viewer 的 Stack Chart。
- 实现进度：以下实施清单全部未完成，不表示已提交或已上线。
- 验收状态：未完成原生窗口点击延迟、内存峰值和大数据交互验收。

## 1. 问题与目标

CPU 数据较大时，切换到 Stack Chart 或点击图中栈块出现明显卡顿。

优化目标是在保留真实样本、时间区间、线程归属和栈块身份的前提下，让界面工作量主要随当前视口和显示分辨率变化，而不是随完整栈块列表线性增长。

本方案不是删除细小栈块或截断原始采样，也不是把隐藏或未绘制的数据解释为不存在。

## 2. 已确认的诊断证据

### 2.1 逐块交互组件过多

[StackChartCanvas.kt](../../presentation/src/main/kotlin/com/androidperformancestudio/presentation/StackChartCanvas.kt) 使用 Canvas 绘图，但还通过 `visible.forEach` 为栈块创建独立的 `Box + clickable + semantics`。

- 绘制部分减去 1 像素间隔后，跳过没有剩余绘制宽度的块。
- 交互覆盖层只检查 `rect.width > 0`，不超过 1 像素的块仍可能创建组件。
- 覆盖层不是惰性列表，组件数量没有像素级预算。
- 切换离开再进入 Stack Chart 时，当前选中面板分支重新进入组合，局部 `remember` 不能充当跨标签页缓存。

因此，即使可见矩形很少，也可能建立大量不可辨认、甚至布局取整后没有可见宽度的交互节点。

### 2.2 重复扫描与绘制

[StackChartPresenter.kt](../../presentation/src/main/kotlin/com/androidperformancestudio/presentation/StackChartPresenter.kt) 的 `visibleBlocks` 仅按时间范围过滤，没有提前按可见深度和像素宽度裁剪。

- Canvas 和交互覆盖层分别遍历时间范围内的块，并分别计算矩形。
- 点击导致选中状态变化后，需要重新遍历相关栈块并更新绘制或交互状态。
- 满足文字显示条件的块在绘制循环中调用 `textMeasurer.measure`。
- Canvas 命中测试使用 `lastOrNull`，控制器校验使用 `blocks.any`，详情查找使用 `firstOrNull`，没有专用的栈块 ID 索引。

控制器位置：[ReportController.kt](../../application/src/main/kotlin/com/androidperformancestudio/application/ReportController.kt)。

详情位置：[FirefoxReportDetails.kt](../../presentation/src/main/kotlin/com/androidperformancestudio/presentation/FirefoxReportDetails.kt)。

### 2.3 数据规模会被栈深放大

[StackChartProjector.kt](../../profile-analysis/src/main/kotlin/com/androidperformancestudio/profileanalysis/StackChartProjector.kt) 遍历保留样本的每一层栈帧，构造候选块并尝试合并相邻区间。

- 关键规模不仅是采样数，还包括所有样本栈深之和。
- 合并要求线程、深度、帧和相邻时间区间等条件满足。
- 多线程交错、帧变化和碎片化区间会降低合并率。
- 当前快照保留完整的 `List<StackChartBlock>`，没有显示分辨率相关的数量上限。

这说明深栈和大量碎片块比单纯的文件大小或采样数量更能解释该问题。

### 2.4 普通点击不会重新查询数据库

`ReportController.selectTab` 只更新标签页及相关界面状态；`selectStackChartBlock` 校验已有块并更新选择。单纯切换标签或选中色块，不会重新提交整份投影查询。

筛选、时间范围、变换等语义输入变化会触发投影刷新，后台计算和内存分配可能形成额外竞争，但不能把它当作普通点击卡顿的默认解释。

## 3. 本机样本验证与边界

诊断使用最近会话 `capture-ce1ce89a-9c11-4891-99d9-ff908d6ba4e9` 的 `profile.sqlite`，以只读 JDBC 连接、无筛选、完整时间范围调用实际栈加载器和 Stack Chart 投影器。

得到的规模为：

- 采样数：5,542。
- 唯一帧数：8,401。
- 栈帧出现总次数：332,564。
- 合并后的栈块数：237,703。
- 最大深度索引：291。

按当前矩形计算和覆盖层条件，在图宽 1,000 像素、从深度 0 开始显示 30 个栈层的视口下计算：

- 可创建的交互覆盖组件：86,705 个。
- 不超过 1 像素的覆盖组件：83,727 个。
- 满足绘图宽度条件的块：2,978 个。

以上组件数量是代入现有布局条件得出的数量，不是对用户原生窗口布局树的直接计数。

单独投影的三次观测约为 75、50、37 毫秒。这些数据来自临时诊断进程，不包含原生窗口组合、布局、绘制和输入处理，也不是稳定的性能基准或实际点击耗时。

尚未取得卡顿瞬间的原生 UI 线程采样，不能据此给出完整的耗时占比，也不能排除特定交互时的瞬时 GC 或后台计算竞争。

## 4. 行为与数据保护约束

- 保留原始采样、完整投影、线程身份、帧身份和 `StackChartBlockId`。
- 显示级裁剪、聚合或细节级别调整不得改变分析统计和导出证据。
- 保留缩放、平移、纵向滚动、拖选时间范围、选中状态和详情联动。
- 维持现有区间边界规则、重叠块命中规则和稳定顺序。
- 不能为了减少节点而移除键盘和无障碍能力。
- 不把测试使用的逐块 `testTag` 作为保留大量生产交互组件的理由。
- 优先核对并复用现有 Flame Graph 的虚拟化或索引工具；是否适用须由后续实现确认。
- 不引入新的可视化运行时或依赖，不扩展为无关的 CPU Profiler 重构。

## 5. 待实施方案

### P0. 建立能够暴露问题的回归与基准

- [ ] 增加真实样本对应的深栈、碎片化、多线程交错测试数据。
- [ ] 记录投影块数、当前视口块数、亚像素块数、组合节点数和峰值内存。
- [ ] 分别测量首次进入、重复切换、选中栈块、缩放、平移和纵向滚动。
- [ ] 区分数据库加载、投影、组合、布局、绘制和输入反馈耗时。
- [ ] 固定基准机器、JDK、显示缩放、窗口尺寸和样本身份。

### P1. 移除逐块交互覆盖层

- [ ] 以 Canvas 统一处理指针输入，不再为每个栈块建立 `Box + clickable`。
- [ ] 通过视口索引完成命中测试，返回真实栈块 ID。
- [ ] 为键盘和无障碍提供受控的可导航语义窗口，避免重新建立全量语义节点。
- [ ] 将依赖逐块标签的 UI 测试调整为坐标命中、选择结果和语义行为验证。
- [ ] 验证组件数量不再与完整栈块列表同比增长。

这一阶段优先消除已经确认的高数量级节点开销，不改变分析数据。

### P2. 视口、像素裁剪与绘制缓存

- [ ] 同时按时间范围和可见深度获取候选块，避免在每次绘制中扫描完整列表。
- [ ] 使用能够正确处理同深度、多线程区间重叠的索引，不直接假设所有区间互不重叠。
- [ ] 为当前视口计算一次矩形，供绘制、命中和选中状态使用。
- [ ] 不绘制没有可辨认像素宽度的独立矩形；必要时采用显示级像素聚合。
- [ ] 聚合保留对应原始块集合，缩放后恢复细节，不能制造单个精确块的假象。
- [ ] 缓存文字布局，缓存键包含文本、可用宽度、字体和缩放等实际布局输入。
- [ ] 将选择高亮与基础绘制数据分开，避免仅切换选中项就重建全部绘制数据。

### P3. 点击路径与标签页状态

- [ ] 按不可变快照建立 `blockId -> block` 索引，替换选择校验和详情查询中的全表扫描。
- [ ] 明确时间、深度、线程及绘制顺序共同决定的命中规则。
- [ ] 评估标签页重入时可复用的轻量视口、索引和布局缓存，避免无界缓存整份界面。
- [ ] 缓存绑定会话、查询、快照版本、视口和尺寸；新会话或新投影不得复用旧结果。
- [ ] 验证普通点击仍然不触发数据库查询或完整投影刷新。

### P4. 依据测量结果优化后台投影

- [ ] 如果 P1 至 P3 后投影仍占主要耗时，再减少候选块、字符串 ID 和中间集合的重复分配。
- [ ] 评估共享过滤、变换结果，避免多个面板重复处理相同输入。
- [ ] 为长时间 CPU 循环增加合适的取消检查，减少过期查询继续消耗 CPU 和内存。
- [ ] 验证结果仍按查询代次发布，旧结果不能覆盖新查询。
- [ ] 任何紧凑存储或结构共享均保持现有不可变数据和身份语义。

本阶段是条件性优化，不作为推迟解决界面节点膨胀的理由。

## 6. 待补测试矩阵

- [ ] 真实样本：5,542 条采样、237,703 个栈块对应的全范围与窄范围视口。

- [ ] 交互连续性：切换标签、选中、取消选中、缩放、拖选和详情开关。
- [ ] 可访问性：键盘导航、焦点、选中反馈和无障碍描述。
